Build a portfolio-grade product called AgentOps Command Center.

This is a multi-agent enterprise operations platform for portfolio companies. It should prove that this system is more than a chatbot: agents collaborate, execute workflow steps, create logs, use tools, require human approvals, and produce traceable outputs.

Core goal:
Create a polished, functional Replit demo that future clients can immediately understand as:
“A multi-agent enterprise ops platform with human-in-the-loop approval, shared memory, workflow logs, and admin visibility.”

Tech stack:
- Frontend: React + Vite + TypeScript
- Styling: TailwindCSS
- UI style: shadcn-inspired components, premium SaaS dashboard feel
- Backend: Python FastAPI
- Database: PostgreSQL if available, otherwise SQLite for local development with clean repository/service abstraction so Postgres can be swapped in later
- Agent orchestration: create a clean orchestration layer that can later be upgraded to LangGraph. If LangGraph can be installed cleanly, use it. If not, create a LangGraph-style state-machine orchestrator with clear nodes and edges.
- LLM support: OpenAI-ready via environment variable OPENAI_API_KEY, but the app must also work in deterministic demo mode without an API key.

Important:
Do NOT build a generic chatbot.
Build a dashboard-backed workflow system where every agent action is visible, logged, and traceable.

Product name:
AgentOps Command Center

Primary demo scenario:
A portfolio company submits this request:
“We need to onboard a new contractor for a roofing project in Texas.”

The workflow should run through these agents:

1. Ops Agent
- Classifies the request
- Identifies the business function
- Determines the required workflow path
- Creates initial task breakdown

2. Legal / Compliance Agent
- Checks required documents
- Flags compliance needs
- Mentions contractor agreement, W-9, insurance certificate, state/local considerations, safety documentation

3. Finance Agent
- Estimates budget/payment workflow
- Flags payment terms, approval thresholds, invoice setup, and risk level

4. Marketing / Communications Agent
- Drafts a client-facing or contractor-facing message
- Creates a polished communication draft

5. Human Approval Queue
- Creates approval item
- Human admin can approve or reject
- Approval decision is logged

6. Final Output
- Generates final workflow summary
- Shows agents involved, tools used, approval status, next actions, and full timeline

Agent orchestration requirements:
Create a backend service that runs this workflow:

submit_request
→ ops_triage
→ retrieve_memory_context
→ legal_compliance_review
→ finance_review
→ communications_draft
→ create_human_approval
→ wait_for_human_approval
→ finalize_workflow

Each stage must:
- Save an AgentStep
- Save one or more ToolCall records if tools are used
- Save ActivityLog entries
- Update WorkflowRun status
- Return structured JSON output

The workflow must be resumable after human approval.

Demo mode:
If OPENAI_API_KEY is missing, use deterministic high-quality generated outputs for the roofing contractor scenario.
The output should look realistic and polished, not placeholder text.

Live mode:
If OPENAI_API_KEY exists, allow agents to generate outputs through a small LLM abstraction layer.
Keep prompts safe and structured.
The agent output must be saved as structured JSON.
